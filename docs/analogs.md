# Обзор аналогов и формулировка новизны

Дата обзора: 2026-11-12. Источники — открытые материалы производителей и научные публикации; сведения
о коммерческих системах взяты из маркетинговых и пользовательских материалов, независимых сравнительных
испытаний этих функций не найдено. Отсутствие функции в таблице означает «не найдено в открытых
источниках», а не утверждение, что её нет.

## 1. PLM-системы

**Siemens Teamcenter.** Развитое управление изменениями (ECR/ECO, маршруты согласования), анализ
применяемости (where-used) по структуре изделия, трассируемость требований в модуле MBSE. В 2025–2026 гг.
заявлены Teamcenter Copilot (анализ влияния изменения, качество требований, генерация тестов) и
«AI BOM agent», анализирующий структуру BOM и затронутые сборки [1, 2]. Проверка требований выполняется
по правилам INCOSE [2]. Анализ строится по связям, *уже занесённым в PLM*; извлечение связей и
численных ограничений из неструктурированных документов (ТУ, расчёты, паспорта) не описано.

**Dassault Systèmes 3DEXPERIENCE (ENOVIA, CATIA Reqtify).** Требования, сквозная трассируемость и
анализ влияния «вверх/вниз» по цепочке артефактов (DOORS, модели, код, изделие) [3, 4]. AI-функции
CATIA Magic: генеративное извлечение требований, подсказки по модели, виртуальные ассистенты [5].
Анализ влияния — по явно установленным трассировочным ссылкам.

**PTC Windchill + Codebeamer.** Управление изменениями с отображением влияния на изменения, требования
и конфигурации; Codebeamer AI — генерация требований и тестов, выявление «проблемных» требований [6, 7].

**Aras Innovator.** Открытая платформа (open API), двунаправленная трассируемость в цифровой нити,
анализ влияния изменения требования на детали [8, 9]. Настройка требует участия опытного администратора.

**Отечественные PLM.** ЛОЦМАН:PLM (АСКОН) — модуль управления изменениями и извещениями, связанные
извещения, управление требованиями [10, 11]. T-FLEX PLM (Топ Системы) — T-FLEX DOCs (состав изделия,
версии, конфигурации), отдельный модуль требований T-FLEX RM [12, 13]. Сведений о семантическом
поиске, автоматическом выявлении противоречий или применении LLM в открытых источниках не найдено.

## 2. RAG-платформы

**RAGFlow (InfiniFlow, Apache 2.0).** Разбор документов (OCR, таблицы, макет), гибридный поиск
(вектор + BM25 + переранжирование), ответы со ссылками на фрагменты, локальный запуск через Docker [14].
Аналогично Dify, AnythingLLM и др. Это средства поиска и ответа на вопросы: в них нет модели предметной
области (компонент, параметр, единица, ограничение), поэтому они не проверяют численную совместимость и
не строят цепочки последствий.

**GraphRAG (Microsoft, Edge и др., 2024).** Граф сущностей строится LLM, для сообществ графа заранее
генерируются сводки; метод превосходит обычный RAG на «глобальных» вопросах по полноте и разнообразию
ответов [15]. Граф нетипизированный (для инженерных ограничений), связи — результат генерации LLM без
формальной проверки.

## 3. Научные работы

- **Анализ влияния изменений в требованиях на ЕЯ:** Arora, Sabetzadeh, Goknil, Briand (RE 2015) и
  инструмент NARCIA — NLP-ранжирование требований по вероятности затронутости, 14 сценариев на двух
  промышленных кейсах [16, 17]. Работает внутри набора требований, без модели компонентов и физики.
- **Метод прогнозирования изменений CPM** (Clarkson, Simons, Eckert, 2004): матрица DSM со значениями
  вероятности и последствий распространения, задаваемыми экспертами [18]. Распространение по
  физической природе — основа, но модель строится вручную на интервью.
- **Противоречия в требованиях:** гибрид формальной логики и LLM (Gärtner, Göhlich, ALICE, 2024) —
  60 % найденных противоречий, лучше «чистой» LLM [19, 20]; SAT/SMT + LLM (ASE 2024) [21]; NLI-оценка LLM
  на полусинтетических автомобильных требованиях (21 тыс. пар) [22]; сочетание кластеризации и LLM
  (RE 2025) [23]. Общая тенденция: гибриды с формальными методами превосходят LLM. Работы
  сосредоточены на парах требований, а не на связи «требование — характеристика компонента — материал».
- **KG + LLM для инженерных моделей:** построение многоуровневой модели отказов из проектной
  документации в виде графа знаний с LLM-агентом (PSAM 18) [24]; позиция Siemens о сочетании GNN и LLM:
  «чистая» LLM даёт убедительный, но не подкреплённый структурой ответ [25].

## 5. Ниша

PLM-системы надёжно анализируют влияние изменений **по связям, которые уже внесены в систему**:
структура изделия, трассировочные ссылки, извещения. Значительная часть ограничений при этом живёт в
неструктурированных документах — ТУ на покупные изделия, расчётах, паспортах, ПМИ, картах уставок, —
и их совместимость с новым значением параметра проверяется вручную. RAG-платформы находят такие
фрагменты, но не понимают, что «≤ 90 °C» в ТУ уплотнения — это предел, который новое требование
«100 °C» нарушает.

Ниша EIS — **предварительный этап**: автоматически построить из разнородной документации
типизированный граф «требование — характеристика — компонент — материал — документ — испытание» с
доказательствами и на нём проверять изменения формально. EIS не заменяет PLM, а дополняет её:
результаты (связи, противоречия, перечень документов на пересмотр) могут передаваться в PLM как
предложения для извещения об изменении.

## 6. Итоговая научная новизна

Из пяти потенциальных элементов, предложенных в задании, после обзора сохраняются три (в уточнённой
формулировке), два признаны не новыми:

1. **Модель «характеристики» как общего узла ограничений.** Требования разных документов к одной паре
   (субъект, параметр) приводятся к единому узлу с нормализованным интервалом и видом
   (требование / возможность / уставка / номинал). Это позволяет одновременно (а) находить все
   документы, задающие изменяемую величину, и (б) формально сравнивать интервалы с учётом единиц.
   В рассмотренных системах трассировка ведётся между артефактами, а не через нормализованную величину.
2. **Распространение изменения с учётом физической природы параметра в сочетании с формальной
   проверкой.** Тип связи, по которой распространяется изменение (контакт со средой, граница давления,
   путь нагрузки, состав, материал), определяется физической величиной; производные величины
   вычисляются по правилам (M = 9550·P/n). Близкая идея есть в CPM, но там вероятности задаются экспертом
   по DSM, а не извлекаются из документов; в PLM распространение идёт по структуре без учёта величины.
   Вклад измерен абляцией: без учёта физики F1 по компонентам падает с 0,96 до 0,91, без фильтра
   документов по содержанию F1 по документам — с 0,94 до 0,77.
3. **Классификация противоречий по типу «требование — возможность — материал — уставка» с
   трёхуровневым статусом** (подтверждено / потенциально / недостаточно данных). Работы [19–23]
   сравнивают пары требований; EIS сравнивает требование с возможностями компонентов и пределами
   материалов через граф. Гибрид правил и графа находит 10 из 10 внесённых противоречий против 7 у
   правил без графа и 2 у поиска по сходству.

Не признаны новыми: **ответы с обязательной ссылкой на источник** (есть в RAGFlow и др.) — в EIS это
инженерная реализация с фильтром чисел, отсутствующих в цитате; **оценка достоверности** результата —
в EIS это эвристика (произведение уверенностей извлечения и связей), а не метод, и её калибровка не
проводилась.
