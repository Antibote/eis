# Журнал архитектурных решений (ADR)

Кратко: решение → причина → последствия. Новые решения добавляются в конец.

**ADR-01. Модульный монолит вместо микросервисов.** Один FastAPI-процесс, сервисы — Python-пакеты с
интерфейсами (`GraphStore`, `Embedder`, `LLMProvider`). Причина: сроки конкурса, простота воспроизведения.
Последствие: масштабирование — вертикальное; разделение на сервисы возможно по границам пакетов.

**ADR-02. Rule-based извлечение — основной метод, LLM — опциональный.** Нет GPU; требование работы без
внешнего API; воспроизводимость эксперимента. Правила опираются на морфологию (pymorphy3) и словарь
параметров предметной области (`extraction/lexicon.py`), не на шаблоны генератора.

**ADR-03. Разделение формулировок на dev/test.** Генератор датасета для каждого требования имеет
варианты формулировок двух непересекающихся наборов. Правила разрабатываются по `dev`, метрики
сообщаются по `test`. Первый прогон на `test` и найденные ошибки зафиксированы в `docs/experiments_log.md`.

**ADR-04. Эталон сценариев задаётся вручную.** Затронутые компоненты, документы и испытания для
5 сценариев записаны в `dataset/generator/model.py` с обоснованием, а не вычислены алгоритмом системы.

**ADR-05. Узел «Характеристика» (Constraint).** Требования из разных документов к одной паре
(субъект, параметр) ссылаются на общий узел `con:<субъект>:<параметр>` (CONSTRAINS), а зависимости
компонентов направлены на этот узел (DEPENDS_ON). Это позволяет находить все документы, задающие
значение изменяемой характеристики, и сравнивать их между собой. Введены типы CONSTRAINS и CHARACTERIZES.

**ADR-06. Направление DEPENDS_ON = «свойства источника зависят от цели».** «Вклад в массу» кодируется
как «характеристика массы зависит от компонента»; «рама воспринимает нагрузку от двигателя» — «рама
зависит от двигателя».

**ADR-07. Классы влияния и физика распространения.** Анализ изменения разделяет подтверждённое
(формальное нарушение ограничения), прямое (явная зависимость), потенциальное (транзитивно/на пределе)
влияние. Распространение по составу и материалам зависит от физической природы параметра
(`domain/engineering.py`). Эффект измеряется абляцией.

**ADR-08. Хранение: исходные файлы на диске, база знаний — JSON-снимок в БД.** Граф строится в памяти
(NetworkX) из снимка за доли секунды. Нормализованные таблицы узлов/рёбер и адаптер Neo4j отложены:
на результат исследования не влияют. Изоляция данных — по `project_id` во всех таблицах и проверкам доступа.

**ADR-09. Полная переобработка проекта при загрузке документа.** Межпроектные ссылки («ТЗ п. 3.2.1»)
и реестр компонентов из спецификации требуют глобального прохода; на корпусе 14 документов — ~0,5 с.
При росте корпуса — инкрементальная обработка с пересвязыванием (план).

**ADR-10. Защита от prompt injection.** Фрагменты с признаками инструкций для ИИ помечаются при
загрузке и не используются как источник фактов; текст документов передаётся LLM только как данные;
ответ LLM проходит citation guard (предложения без ссылки или с числами, отсутствующими в цитате,
удаляются). Внешние LLM выключены по умолчанию и требуют разрешения на уровне пользователя.

**ADR-11. Эмбеддинги — `intfloat/multilingual-e5-small` на CPU, точный поиск в NumPy;** при
недоступности модели — TF-IDF по символьным n-граммам (работа без сети).

**ADR-12. Базовый метод по сходству (E3) получает лучший порог.** Порог τ подбирается по максимуму F1
на том же наборе — это завышает его результат и делает сравнение консервативным для гибридного метода.
